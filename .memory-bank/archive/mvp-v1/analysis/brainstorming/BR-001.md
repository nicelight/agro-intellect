## Problem Space

The project is a greenfield AI-first training ground for building agentic systems, using one hydroponic tomato as a small controllable model of a future farm-scale monitoring system.

The product must also be useful as a personal daily assistant: it should help observe the plant, collect photos and pH/EC data, produce cautious recommendations, create follow-up tasks, and preserve evidence for future evaluation and learning loops.

## Goals

- Learn how to design, build, test, and govern agentic workflows through SDD and Memory Bank discipline.
- Build a practical daily workflow around `tomato_001`.
- Keep agents single-competence and prevent cross-role decision leaks.
- Separate agent conclusions, UI explanations, internal reasoning, and dataset truth.
- Preserve photo, timeline, review, and dataset evidence so future training data is not polluted by unverified hypotheses.
- Keep the MVP small enough to finish and verify.

## Constraints

- `project_dossier.md` is upstream dossier context until narrower specs own decisions.
- Design Specs become normative after `/spec-init` and `/spec-design`.
- Agno is execution SDK only, not source of truth and not the Agent Chat Bus.
- Agno Team `coordinate` is forbidden in MVP.
- PostgreSQL/read model is runtime authority for mutable operational state.
- Photos stay in filesystem/object storage, not as PostgreSQL or InfluxDB blobs.
- `timeline.jsonl` is append-only audit/export log.
- Physical changes require Safety Gate and human approval.
- Agent-labeled observations are not ground truth and must not become training data without review/evidence gates.
- InfluxDB is future-only until sensors exist.

- Future-back reasoning from farm-scale agentic system to tomato MVP.
- Boundary identification for agents, data authority, UI Feed, Agent Chat Bus, and dataset governance.

## Raw Ideas

1. Start with a daily morning check-in ritual.
2. Treat photo upload as the central observation event.
3. Require `plant_id` on every photo and related event.
4. Keep MVP to one plant: `tomato_001`.
5. Capture manual pH/EC before any strong hydroponic recommendation.
6. Let Vision Observation Agent describe visible symptoms without diagnosing.
7. Let Plant State Agent maintain probable/unknown/conflict state over time.
8. Let Hydroponics Advisor Agent produce cautious recommendations and missing-data requests.
9. Let Safety Gate convert risky advice into pending approval flows.
10. Let Companion Agent explain conclusions to the user in plain language.
11. Let Task & Follow-up Agent create measurement tasks and follow-up checks.
12. Keep Training Data Curator mostly silent and delayed.
13. Use `MessageEnvelope` as the domain adapter output.
14. Split Agent Chat Bus from UI Feed.
15. Make `ui_spoiler_note` visible to humans but non-consumable by agents.
16. Track `model_version` and `prompt_version` in agent reports.
17. Store photo manifests as generated JSON snapshots near photos.
18. Keep mutable review/dataset/sync state in PostgreSQL.
19. Use `timeline.jsonl` for audit/export, not as mutable authority.
20. Build schema validation before complex agent behavior.
21. Include valid and invalid schema examples early.
22. Mock Vision Agent before wiring real vision.
23. Prohibit direct publication from Agno invocation to Agent Chat Bus.
24. Require runtime decision after agent calls: `speak`, `silent`, `clarify`, or `escalate`.
25. Avoid long default agent messages.
26. Use quoted-detail replies only when the user asks for detail.
27. Add lazy upload/sync only after local workflow works.
28. Add sensors and InfluxDB only after stable MVP.
29. Defer production multi-user concerns.
30. Use learning loop only through evidence, follow-up, and review gates.

## Clusters / Themes

- Product ritual: daily check-in, photo upload, manual measurements, user-readable response, tasks, and follow-up.
- Agent boundaries: single competence, domain adapters, clear runtime decisions, no hidden cross-agent use of UI-only notes.
- Data authority: PostgreSQL for mutable state, files plus JSON snapshots for dataset artifacts, timeline for audit/export.
- Safety and HITL: no physical action without fresh data, Safety Gate, and human approval.
- Dataset governance: statuses, evidence refs, delayed curator decisions, no training on raw or agent-labeled hypotheses.
- MVP sequencing: foundation, schemas, Agent Chat Bus, first workflow, learning loop, sync, sensors.

## Rejected Directions

- Production SaaS or multi-user product in MVP.
- Autopilot control of pumps, dosing, pH, EC, or light.
- Complex expert panel or dataset registry in first MVP.
- Storing photo binaries in PostgreSQL or InfluxDB.
- Using Agno Team `coordinate` as domain coordinator.
- Treating agent diagnosis as confirmed truth.
- Using eval or holdout data for fine-tuning.
- Building sensor runtime dependency before sensors exist.
