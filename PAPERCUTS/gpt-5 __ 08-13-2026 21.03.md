# Papercuts

- A quick FT-015 queue summary assumed full task records inside
  `.memory-bank/tasks/index.json` and an `acceptance_criteria` field in each
  card. The index actually stores only `{id, file}` entries and claim text is
  carried by `evidence_required`/`verification_targets`, so the first `jq`
  projection failed instead of producing a useful summary.
- A large `apply_patch` wrapper used a JavaScript template literal containing
  unescaped Markdown backticks from task IDs. The wrapper failed before the
  patch ran; subsequent multi-file patches must remove or escape embedded
  backticks at the JavaScript boundary.
- The custom direct-anchor audit initially treated project AC locators as exact,
  case-sensitive GitHub heading slugs and collapsed repeated slug hyphens. The
  task convention uses case-insensitive AC prefixes, while GitHub preserves a
  double hyphen when punctuation is removed between spaces; the audit must
  normalize case, allow the heading-text suffix, and retain GitHub slug spacing.
- A direct Draft 2020-12 validation import of `ajv/dist/2020.js` failed because
  this workspace has no project-local AJV package even though the system module
  exists under `/usr/share/nodejs`; validation must use the repository lint
  path or the explicit system module path instead of assuming Node package
  resolution.
